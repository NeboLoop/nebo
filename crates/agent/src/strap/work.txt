### work — Workflow Management & Execution
USE THIS when: user wants to manage or run automated workflows.
Workflows BELONG TO AN AGENT. Calls scope to YOU by default; pass agent: "Name" to manage another agent's workflows. When the owner asks you to add or change an EMPLOYEE's duties, the workflow goes on that employee — work(action: "create", agent: "Content Creator", ...) — NEVER on yourself. (agent(resource: registry, automations/add_automations) also works when creating/configuring an agent wholesale.)

**Lifecycle actions (no resource):**
- work(action: "list") — List installed workflows and their status (add agent: "Name" for another agent's)
- work(action: "create", name: "My Workflow", definition: '{"trigger": {"type": "schedule", "cron": "0 9 * * MON-FRI"}, "activities": [{"id": "run", "intent": "what this accomplishes", "steps": ["concrete step 1", "concrete step 2"]}]}') — Create a workflow. Activities are the only executable unit; a top-level "steps" array is shorthand for one activity. Definitions with no runnable activities are rejected.
- work(action: "update", name: "my-workflow", definition: '{...}') — Full-replacement edit of an existing workflow: same definition shape as create, run history stays attached, errors if the name doesn't exist
- work(action: "delete", name: "my-workflow") — Delete one of this agent's workflows by name
- work(action: "install", code: "WORK-XXXX-XXXX") — Install from marketplace code
- work(action: "uninstall", id: "workflow-id") — Uninstall a marketplace-installed workflow (install id, not name)

**Dispatch to workflow (set resource = workflow name):**
- work(resource: "weekly-report", action: "run") — Run the workflow (returns immediately with run_id)
- work(resource: "weekly-report", action: "run", inputs: {"week": "2024-03"}) — Run with inputs
- work(resource: "weekly-report", action: "status") — Check latest run status
- work(resource: "weekly-report", action: "runs") — List recent runs
- work(resource: "weekly-report", action: "toggle") — Enable/disable

First use work(action: "list") to see available workflows and their names, then dispatch with resource.
When creating a workflow, use the workflow-creator skill for guided step-by-step creation.
Workflows run as background subagents — run returns a run_id immediately.
Use status to check progress. Workflows have their own tool access and token budgets.
